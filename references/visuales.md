# Iconos, gráficos, demos y capturas

## 2D y 3D

Aplicar 2D por defecto: iconos vectoriales coherentes, diagramas simples, tarjetas, ilustraciones planas y flujos claros. Aplicar 3D cuando se solicite: objetos isométricos, dispositivos, profundidad y sombras suaves; mantener cámara, iluminación, materiales y paleta consistentes. La elección afecta ilustraciones, sin deformar tablas, precios ni logo. Admitir mezcla solo si el pedido lo requiere o si aporta claridad.

Para ilustraciones raster 3D/2D usar la herramienta de generación de imágenes disponible y su skill. Para diagramas exactos, iconos simples y gráficos con datos usar SVG o herramientas de gráficos/código, evitando imágenes generadas para cifras o relaciones precisas. Componer textos y precios posteriormente con tipografía real. No inventar datos ni gráficos de crecimiento decorativos que sugieran resultados garantizados.

## Iconos

Crear o seleccionar una familia de iconos de trazo uniforme para alcance, web, software, calendario, pagos, soporte e integraciones. Usar SVG propio o biblioteca disponible con licencia adecuada. Si se solicitan iconos ilustrados 3D, generar recursos consistentes. Acompañar símbolos ambiguos con etiquetas, evitar emojis de aspecto variable y no colocar iconos en cada frase.

## Demos de software

Distinguir demo real, prototipo interactivo y maqueta conceptual. Pedir o recuperar URL y accesos autorizados cuando corresponda. Usar datos ficticios claramente identificados. Mostrar módulos representativos del alcance sin sugerir que están implementados cuando solo son propuestos.

Para un presupuesto, incluir por defecto una maqueta o capturas si ayudan; no construir una aplicación completa salvo solicitud. Rotular «Ejemplo ilustrativo», «Prototipo» o «Demo» cerca del recurso. Si se pide demo funcional, aplicar la skill de Sites disponible u otra vía autorizada, implementar solo el flujo acordado y comprobarlo. No publicar, desplegar ni modificar producción sin autorización; una solicitud expresa de publicar sí autoriza ese paso. No simular pagos, guardado, integraciones o funciones como reales si no están implementados.

Enlazar demos verificadas con texto clicable. Incluir credenciales de prueba únicamente si son seguras y se autoriza compartirlas. No incluir contraseñas de producción. Añadir QR solo si aporta utilidad y verificar que sea escaneable.

## Imágenes y capturas

Priorizar material del usuario, capturas reales y recursos oficiales autorizados. Registrar su fuente. Elegir una imagen por propósito, mantener proporciones y resolución, recortar sin ocultar contexto relevante y poner pie explicativo. No exponer datos personales o secretos en capturas. No retocar una interfaz para atribuirle funciones inexistentes; una nueva interfaz dibujada debe identificarse como propuesta.

Admitir marcos de dispositivos y ampliaciones legibles. Reservar marcas rojas o flechas para señalar detalles realmente útiles; no convertir el presupuesto en tutorial. Usar rectángulos sin relleno y etiquetas fuera de controles. Para pantallas densas mostrar contexto y detalle en páginas separadas. Revisar visualmente todas las imágenes al tamaño de entrega.
